# 09.16 Context - Cordex Method OS V1

## Problem

Cordex Gym OS has strong operational primitives, but the core product vocabulary is still gym-specific. Cordex now needs an internal Method OS layer that represents clients, segments, playbooks, events, tasks, human actions and measured outcomes horizontally.

## Decision

Keep `Gym` as the physical tenant table and `gym_id` as the isolation key. Expose Method OS API fields as `cordex_client_id` where useful, backed by `gyms.id`, so the V1 remains brownfield-safe.

## Constraints

- No full SaaS rebuild or broad rename.
- No autonomous outbound messaging.
- No hardcoded academia rules in the core; segment specifics live in playbooks.
- Existing screens and tenant guardrails must continue to work.
