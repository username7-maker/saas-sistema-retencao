# Bioimpedance end-to-end audit — 2026-09-24

Scope: capture/upload, image parsing, form population, persistence, chronology,
semantic report, technical PDF, AI narrative and Actuar synchronization. This
is an audit only; no application code was changed in this pass.

## Confirmed findings

1. **P1 — Technical PDF overflows its intended sheets.** A deterministic
   three-assessment fixture with two body measurements and two skinfolds
   rendered as five A4 pages. The second planned sheet flowed onto another
   page, a footer overlapped the composition table, and a single history chart
   was orphaned on page five. The current tests inspect HTML content, not
   printed pagination or clipping. Source: `premium_report_service.py`
   (`.clinical-page` uses `min-height: 1123px`, `height: auto`, and forced page
   breaks).
2. **P1 — An unreviewed OCR evaluation can be queued for external sync.** The
   API allows `source=ocr_receipt`, `reviewed_manually=false` (intentionally
   allowing a draft), while `prepare_body_composition_sync_attempt` does not
   gate on `reviewed_manually` or `needs_review` before creating a pending
   Actuar job. The React UI blocks normal submission, but the API/worker must
   enforce the same safety invariant.
3. **P1 — A newly read image can retain an old weight on update.** The React
   form clears receipt measurements before applying a new OCR result. The API
   then restores the stored `weight_kg` when the new OCR payload has null
   weight because `_preserve_existing_anthropometry_for_ocr_update` includes
   weight. The saved value can therefore differ from the empty field shown
   during review. This needs an explicit policy for shared anthropometry
   weight, plus a UI/API test for a replacement image without readable weight.
4. **P2 — AI narrative and single-evaluation assistant can choose a future
   evaluation as the previous one.** `generate_body_composition_ai`,
   `serialize_body_composition_evaluation`, and delivery helpers select the
   latest other evaluation without filtering relative to the target date.
   Entering or sending an older assessment may generate reversed progress
   prose. The V2 report's own chronology is separate and mostly correct.
5. **P2 — Persisted AI comparison bypasses V2 method compatibility.**
   `_compare_with_previous` computes body-fat and weight deltas directly.
   Different official body-fat methods can produce a narrative comparison
   even when the semantic report returns `incompatible_method`. Kommo and
   WhatsApp can reuse this persisted summary.
6. **P2 — Physical age disappears in the V2 technical PDF.** The evaluation
   fixture contained `physical_age=28`, but the printed header showed `-`.
   `physical_age` is absent from `CORE_METRIC_DEFINITIONS`; the V2-to-classic
   PDF adapter searches that absent metric instead of receiving it from the
   canonical report.
7. **P2 — The weight indicator says Normal for 20–220 kg.** The technical PDF
   labels a sample 82 kg value as `NORMAL` against the operational/equipment
   interval 20–220 kg. This reads as a health classification even though that
   interval is not a clinical reference. The reference kind is equipment, but
   the status text does not communicate that limitation.

## Checks that passed

- Backend targeted parsing, persistence, report and AI suites: 123 tests.
- Playwright scanner with real Worker: manual and automatic capture/review,
  2 tests. Anthropometry report browser test: 1 test.
- Prior full validation of the current deployed change: 1370 backend tests
  passed (3 skipped), 302 frontend tests passed, lint and build passed.
- Tenant/member scope is checked on image parse, report and evaluation routes.
- The Tezewa receipt supplied earlier was independently verified against a
  range-free Value-column read; salt, muscle and BMR matched the printed values.

## Validation limits

- No physical Android/iPhone camera was available. Browser E2E uses a
  simulated camera stream.
- Only one real Tezewa receipt was available for a provider read; there is no
  labeled multi-device image corpus or measured false-positive rate.
- No authenticated production member record was changed or exported in this
  audit. The PDF layout check used synthetic evaluations and current code.

## Repair order

1. Block external sync and outward narratives until OCR review is complete;
   make replacement-photo null semantics explicit for weight.
2. Use one chronological, method-aware comparison service for AI summaries,
   assistant text and delivery, aligned with report V2.
3. Fix PDF pagination, restore physical age and remove clinical-sounding
   classification from operational weight bounds. Add rendered-page tests.
4. Build a de-identified, labeled receipt corpus and test actual devices.

## Resolution — 2026-09-24

- The Actuar queue and WhatsApp/Kommo delivery now reject an OCR draft until
  the professional has reviewed it; any pending sync job is cancelled when an
  evaluation returns to unreviewed state.
- Replacing a receipt no longer silently copies the old weight when the new
  image has no readable weight. Anthropometric measurements remain preserved.
- AI prose and assistant deltas use the report domain's per-metric method and
  date checks. Previous-evaluation queries are tenant-scoped and only consider
  earlier dates; same-day historical entries remain conservatively omitted in
  these prose paths.
- The V2 report now retains physical age and does not call the device's broad
  weight range normal. The technical PDF fits its content within A4 sheets and
  places five history charts on one sheet rather than orphaning one.
- Validation: 1377 backend tests passed (3 skipped), 302 frontend tests passed,
  frontend lint and production build passed, scanner browser tests (2) and
  anthropometry browser test (1) passed. A rendered four-page technical PDF
  was visually inspected; a print-layout test checks sheet bounds and footer
  separation. Physical Android/iPhone checks remain pending.
